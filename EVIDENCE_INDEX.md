## 1. Evidence Governance & Classification

To ensure transparency and integrity, all test outcomes and defect reports adhere to a strict evidence classification hierarchy. In accordance with professional testing standards, **no synthetic or fabricated screenshots/logs are generated**.

### Evidence Status Definitions
1. **Verified Runtime Artifact (VRA):** Genuine visual or log capture extracted directly from a running device or emulator (e.g., orientation distortion screenshot).
2. **Static Code & Configuration Proof (SCP):** Concrete source code line references, AST AST patterns, configuration files (`AndroidManifest.xml`, `Info.plist`, `build.gradle`), or local storage inspection (`mmkv.default`) extracted directly from the repository.
3. **Automated Test Runner Output (ATRO):** Execution transcripts generated by the Node.js QA test suite (`qa-test-suite/runner.js`).
4. **Pending Physical Verification (PPV):** Test scenarios where code-level logic points to a defect, but live multi-device confirmation requires dedicated physical hardware not present in the current test workstation.
